# 常见问题

## 当前到底上线了吗？

Pages 预览和正式自定义域均已上线：源码位于 GitHub 私有仓库 `example/example-blog`，`main` 分支由 Cloudflare Pages 自动构建到 `https://example-blog.pages.dev`，正式地址为 `https://blog.example.com`。自定义域 SSL 已启用，Cloudflare DNS 中 `blog` 为代理 CNAME；根域 `https://example.com` 不属于本项目且未修改。

## 为什么开发环境能看到草稿，生产没有？

开发环境保留草稿，方便写作预览。生产 `pnpm build` 会过滤 `draft: true`，因此草稿不会生成文章路由、首页/归档条目、RSS、Sitemap 或 Pagefind 文章索引；仅被草稿引用的 Astro Markdown 图片和封面也会被排除。`public/` 会整体发布，不要把敏感文件放在那里。

## 为什么开发搜索不像真实搜索？

Pagefind 索引在 `pnpm build` 的最后一步生成。开发服务器会明确提示尚未生成索引，不会伪造搜索结果；请用构建后的 `pnpm preview` 验证生产搜索。索引边界和排除规则见 [Pagefind 配置](09-Pagefind配置.md)。

## Cloudflare Pages 应该怎么配置？

使用 GitHub Git 集成，生产分支 `main`，根目录 `/`，构建命令 `pnpm build`，输出目录 `dist`，Node.js 22，pnpm `9.14.4`。GitHub Actions 只做检查，不需要保存 Cloudflare API Token。完整步骤见 [Cloudflare Pages 部署](06-Cloudflare-Pages部署.md)。

## 为什么 DNS 查询有时还会看到旧 A 记录？

迁移前曾观察到 `blog.example.com A 203.0.113.10`，站长已确认域名为新申请且没有旧项目；当前 Cloudflare 控制台已将 `blog` 管理为代理 CNAME `example-blog.pages.dev`，SSL 已启用。代理记录对外可能被展开为 Cloudflare A 地址，递归缓存也可能短暂保留旧结果；使用独立 DoH、Cloudflare 控制台和 HTTPS 实际响应共同判断。根域、`www`、MX/TXT 和其他子域绝不能改。迁移与回滚见 [域名与 DNS 配置](07-域名与DNS配置.md)。

## `pages.dev` 通过后，何时绑定自定义域？

已完成页面、404、SEO、资源、搜索、隐私、HTTPS 和系统 Chrome 验收；如果以后重新绑定失败，保留 `pages.dev`，不要尝试改根域或迁移整个 zone 的 Nameserver。

## 评论会同步给其他人吗？

不会。当前文章页使用本地评论，昵称和评论内容只保存在当前浏览器的 `localStorage` 中，用于个人阅读批注和下次复用昵称。换浏览器、清理站点数据或使用另一台设备后，这些评论不会自动出现；如果需要公开评论流，再单独评估 Giscus 或后端方案。

## 默认昵称从哪里来？

如果访客没有设置昵称，评论区会从本地昵称库随机选一个王者荣耀英雄名并保存。头像不会下载或使用游戏头像，仍按昵称截取最后两个文字生成纯色文字头像。

## Giscus 为什么没有显示？

当前文章页挂载的是 `LocalComments` 本地评论，不挂载 Giscus 组件；Giscus 仓库/分类标识也为空，所以不会加载 `giscus.app`。博客源码仓库是私有仓库，不能直接作为 Giscus 评论仓库；启用前需另建公开 GitHub Discussions 仓库，并阅读 [Giscus 配置](08-Giscus配置.md) 的隐私说明。

## Cloudflare Web Analytics 为什么没有请求？

这是预期行为。当前统计开关关闭；代码还要求生产构建、`features.analytics`、`cloudflareWebAnalytics.enabled` 和非空 `PUBLIC_CLOUDFLARE_WEB_ANALYTICS_TOKEN` 同时满足。本地开发不会加载 beacon。该 Token 是页面公开的站点标识，不是 API Token；启用前应在隐私说明中告知第三方请求与数据用途。

## 本阶段为什么不做 PWA？

当前博客是静态内容站，尚无离线、安装或推送需求。PWA 会引入缓存版本、更新提示、离线回退和调试复杂度；过早加入容易缓存旧文章或第三方脚本。待明确离线使用场景、缓存策略和验收指标后，再单独评估，不影响 Cloudflare Pages 静态部署。

## 本地出现 Node/pnpm 或构建警告怎么办？

项目目标是 Node 22 与 pnpm `9.14.4`。非目标的 Node 23/24 可能显示 Type Stripping 或引擎范围警告，pnpm 11 可能提示 `onlyBuiltDependencies` legacy 配置，Browserslist 数据可能过期，Mermaid 延迟 chunk 可能超过 Vite 500 kB 阈值。这些通常不是失败原因；以 `pnpm check`、`pnpm type-check`、Biome 和 `pnpm build` 的退出码为准，并优先在 Node 22/pnpm 9 环境复现。

## 构建失败时应先查什么？

按顺序清理并重试：确认 Node/pnpm 版本、运行 `pnpm install --frozen-lockfile`、查看 Astro 检查首个错误、确认公开文章 Frontmatter 的 `title`/`description`/日期有效，再单独运行 `pnpm build`。不要同时启动多个 Astro 进程，也不要直接编辑 `dist/`。若是依赖升级引起，参考 [主题升级指南](12-主题升级指南.md)。

## 如何回滚？

代码使用经过审查的 revert 提交；Pages 使用上一份成功部署的 Rollback/重新部署；DNS 只恢复迁移前导出的 `blog` 记录。所有回滚都不得修改根域、MX/TXT 或删除旧部署历史。DNS 回滚不能代替旧主机备份，也不能立即清除全球缓存。

## 需要把 Token 放进 GitHub 吗？

不需要。Pages Git 集成不需要 Cloudflare API Token。当前本地评论不需要 Token。Giscus 配置值和 Web Analytics site token 会进入静态页面，属于公开值；API Token、密码、私钥、数据库连接串和私有内容严禁提交、打印或放进文章。

## 正式显示名称是什么？

当前 `src/config/site.ts` 使用已确认的 `Example Lab` 作为显示名称和占位作者名，域名使用 `example.com`。已配置 GitHub 主页 `https://github.com/example` 和邮箱 `hello@example.com`；真实个人简介仍未提供，不要据此推断姓名或经历。
