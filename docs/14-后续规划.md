## 可选增强

### 评论与隐私

已启用文章页本地评论，昵称和评论内容保存在访客浏览器 `localStorage`，默认昵称从王者荣耀英雄名库随机生成，头像按昵称文字生成。该方案不提供公开讨论、跨设备同步、后台审核或数据备份。Giscus 组件保留为第三方评论备选；若未来启用，应先完成 GitHub Discussions 仓库/分类设置、隐私说明、主题切换和 Swup 验收，再只在需要的 Pages 环境配置公开构建变量。

### Web Analytics

Cloudflare Web Analytics 接入代码已准备但默认关闭。若启用，应明确收集范围、Cookie/请求行为、保留策略和隐私文案；仅设置 site token 不足以启用。不要改用自部署 Umami，除非另有数据存储和运维需求。

### 内容与搜索

- 发布经过编辑的原创文章，逐篇补齐描述、封面替代文本和版权信息。
- 根据真实文章规模评估 Pagefind 索引体积、语言分词和搜索 UI，而不是提前引入后端搜索服务。
- 持续做链接、图片、结构化数据和移动端回归检查。

## 明确暂不实现

以下事项需要独立需求、隐私评估和验收标准，本阶段不提前搭框架：

- 主站 `example.com` 的页面设计、导航和内容。
- PWA、离线缓存、安装提示和推送。原因是当前没有离线场景，缓存失效/版本迁移复杂度会增加维护风险。
- AI 搜索、AI 摘要、AI 问答、多语言和自动翻译。
- Obsidian 自动同步、私有知识库自动公开、自动生成封面和社交媒体发布。
- Newsletter、阅读量、用户账户、服务端数据库和自部署统计。

这些方向都不能成为当前部署的隐含依赖；博客应继续能在无主站、无后端和无第三方 Token 时独立构建。

## 维护节奏与决策记录

- 小型依赖和内容修复：每次变更都跑完整本地检查，保留可回滚提交。
- Fuwari/Astro 大版本：遵循 [主题升级指南](12-主题升级指南.md)，先独立分支和预览，再决定合并。
- 部署或 DNS：记录操作者、时间、旧值、新值、部署 ID、验证结果和回滚点；不在仓库记录凭据。
- 每次启用第三方服务：同步更新 [站点配置](05-站点配置.md)、隐私说明、FAQ 和对应服务文档。

## 完成定义

一个阶段只有在以下条件都满足时才算完成：源码、配置、文档和实际构建行为一致；本地检查通过；远端动作有明确授权；预览或生产验收记录可复现；并且存在不影响根域的回滚方案。
