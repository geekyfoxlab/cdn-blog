# 本地开发

## 前置条件

项目使用 Node.js 22 LTS。`.nvmrc` 已记录主版本 `22`，`package.json` 要求 Node.js `>=22.0.0 <23.0.0`。

项目固定 pnpm `9.14.4`。首次使用前可运行：

```sh
corepack enable
```

检查版本：

```sh
node --version
pnpm --version
```

依赖安装策略同时位于 `package.json` 和 `pnpm-workspace.yaml`：固定的 pnpm 9 使用 `pnpm.onlyBuiltDependencies`，pnpm 11 使用 `allowBuilds`；两者都只允许 `esbuild`、`sharp` 和 `@parcel/watcher` 执行构建必需的安装脚本，并明确禁用 `swup` 的非必要安装后脚本。

## 安装与启动

```sh
pnpm install
pnpm dev
```

Astro 默认在 `http://localhost:4321` 提供开发服务。需要占用其他端口时，可使用：

```sh
pnpm dev --host 127.0.0.1 --port 4322
```

开发环境会显示草稿文章和草稿封面；这是预览行为，不代表它们会被发布。生产构建过滤 `draft: true`，Remark guard 会移除草稿 Markdown 图片，封面虚拟清单也只导入公开文章封面。

## 质量检查

建议按以下顺序执行：

```sh
pnpm check
pnpm type-check
pnpm exec biome check ./src
pnpm build
```

- `pnpm check` 运行 Astro 的组件、类型和 Content Collection 检查。
- `pnpm type-check` 运行 `tsc --noEmit`。
- `pnpm exec biome check ./src` 检查源码格式和 lint 规则，不会改写文件。
- `pnpm build` 先生成静态 HTML，再执行 `pagefind --site dist` 生成搜索索引；Pagefind 只扫描生产公开页面。

构建后可运行：

```sh
pnpm preview --host 127.0.0.1 --port 4322
```

重点检查 `/`、`/about/`、`/archive/`、公开文章、`/rss.xml`、`/sitemap-index.xml` 和 `/robots.txt`。有 Mermaid 文章时还要检查图表 SVG、源码回退、深浅色切换，以及通过 Swup 在首页和文章页之间往返后是否仍能渲染。预览结束后应停止进程，避免占用端口。

## 新建文章

```sh
pnpm new-post my-first-post
```

脚本会在 `src/content/posts/` 创建 Markdown 文件；参数可包含子目录，例如 `guides/my-first-post`。脚本生成的是待编辑模板，发布前必须手动确认：

1. `title` 非空。
2. `published` 是有效日期。
3. `description` 是面向读者的独立摘要。
4. 新模板默认是 `draft: true`；准备发布时再改为 `false`。
5. `tags`、`category` 和 `image` 的值符合 [文章写作规范](04-文章写作规范.md)。

当前 Schema 不支持 `slug`、`cover`、`coverAlt`、`series`、`featured` 或逐文章 `author` 字段；不要自行添加这些字段并期待它们生效。

## 生产边界

生产构建使用 `https://blog.example.com` 作为 Astro `site`，主站地址为 `https://example.com`。草稿不会生成文章路由、首页列表、归档条目、标签/分类统计、RSS 条目、Sitemap URL 或 Pagefind 文章索引；仅由草稿引用的正文图片和相对封面也不会进入生产 Astro 资源清单。`public/` 仍会整体复制，不能用于存放敏感文件。

当前 Giscus 和 Cloudflare Web Analytics 均关闭；GitHub 私有仓库、Cloudflare Pages 生产项目和 `blog.example.com` 自定义域已配置。不要在本地开发阶段写入生产 Token 或直接执行 DNS 变更；完整发布与交接流程见 [开发流程与项目交接](15-开发流程与项目交接.md)。

## 常见问题

### 为什么开发环境能看到草稿？

内容查询在开发环境保留草稿，以便编辑。只有 `pnpm build` / `pnpm preview` 的生产路径会过滤草稿。

### 为什么开发环境没有真实搜索结果？

Pagefind 索引只在 `pnpm build` 后生成。开发环境的搜索面板会明确提示当前没有索引，不会伪造文章结果；要验证真实中文检索，请先构建再运行 `pnpm preview`。完整的索引边界和排查方法见 [Pagefind 配置](09-Pagefind配置.md)。

### 构建时出现哪些可以接受的警告？

- 非目标的 Node.js 23/24 运行时可能提示 Type Stripping 或引擎范围警告；发布和 CI 应使用 `.nvmrc` 指定的 Node.js 22 LTS。
- Browserslist 可能提示 `caniuse-lite` 数据过期；这是数据更新提示，不会阻止构建，依赖升级时再统一更新。
- Mermaid 延迟加载 chunk 可能超过 Vite 默认的 500 kB 告警阈值；图表仍按需加载，后续可单独拆分或调整阈值。
- 使用 pnpm 11 时会提示 `package.json#pnpm.onlyBuiltDependencies` 为 legacy 配置；该字段仍需保留以兼容项目固定的 pnpm 9，`allowBuilds` 同时覆盖 pnpm 11。

这些告警不等于发布失败；仍以 `pnpm check`、`pnpm type-check` 和 `pnpm build` 的退出码为准。

### 为什么公开文章检查失败？

公开文章（`draft` 不是 `true`）必须有非空 `description`。同时检查 Frontmatter 日期、缩进和字段名称是否符合 Schema。

### 可以直接部署 `dist/` 吗？

可以将 `dist/` 作为静态产物交给后续托管流程，但生产发布由 Cloudflare Pages Git 集成负责，构建参数和 DNS 边界见 [Cloudflare Pages 部署](06-Cloudflare-Pages部署.md) 与 [域名与 DNS 配置](07-域名与DNS配置.md)。
