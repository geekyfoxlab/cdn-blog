# 站点配置

## 配置入口

本站业务配置统一位于：

```text
src/config/site.ts
```

该文件导出 `blogConfig`，是域名、站点文案、主题色、头像、横幅背景图、favicon、导航、作者资料、SEO、RSS、页脚、许可证和功能开关的唯一配置源。

Fuwari 原生 `src/config.ts` 是兼容层，只负责把 `blogConfig` 映射为主题需要的 `SiteConfig`、`NavBarConfig`、`ProfileConfig` 和 `LicenseConfig`。日常配置不要改 `src/config.ts`；除非升级 Fuwari 或新增主题字段，否则都改 `src/config/site.ts`。

## 常改变量

`src/config/site.ts` 顶部保留了最常改的一组变量：

```ts
const siteUrl = "https://blog.example.com";
const mainSiteUrl = "https://example.com";
const githubUrl = "https://github.com/example";
const contactEmail = "hello@example.com";
const authorBio = "记录技术实践与学习笔记";
const avatarSrc = "/favicon/favicon-light-192.png";
const avatarAlt = "Example Lab 临时站点图标";
const defaultThemeHue = 140;
const defaultThemeColor = "rgb(20 184 166)";
const themeColorVersion = "2026-07-31-rgb";
const defaultOgImage = "";
const bannerImage = "";
```

- `authorBio` 用于侧栏 Profile 和 About 页的个人简介。
- `avatarSrc`、`defaultOgImage`、`bannerImage` 可以使用 `public/` 下的根路径，例如 `/images/avatar.png`。
- `defaultThemeHue` 是 0 到 360 的色相值，用于生成背景、按钮和辅助色；当前默认为 `140`。
- `defaultThemeColor` 是精确主色，支持 `rgb(...)`、`#hex`、`oklch(...)` 等 CSS 颜色；留空时使用 hue 生成主色。
- `themeColorVersion` 用来刷新访客浏览器里的旧 `hue` 缓存；修改默认主题色后同步改这个字符串。
- 前端调色面板允许访客选择 RGB/HEX 主题色，浏览器会写入本地 cookie：`theme-color` 保存主色，`theme-hue` 保存辅助色相；cookie 优先于站点默认配置，点击重置按钮会清除本地 cookie 并回到 `src/config/site.ts`。
- `bannerImage` 只有在 `blogConfig.appearance.banner.enable` 为 `true` 时显示。
- `defaultOgImage` 用于没有页面封面时的分享图；为空时不输出默认分享图。
- favicon 配置在 `blogConfig.appearance.favicon`，留空时使用 `public/favicon/` 下的默认明暗图标。

## 核心地址

```ts
siteUrl: "https://blog.example.com"
mainSiteUrl: "https://example.com"
```

- `siteUrl` 是博客 Astro `site`、Canonical、Open Graph URL、RSS 回退地址和 Sitemap 的根地址。
- `mainSiteUrl` 只用于导航中的“主站”跨站入口；“返回 Example Lab 主页”返回博客首页。
- 两个地址代表独立站点，不能把博客页面 Canonical 指向主站。
- 配置值不要追加路径、查询参数或片段；内部 URL 工具会按 `trailingSlash: "always"` 生成路由。

## `blogConfig` 字段

| 分组 | 主要字段 | 当前值或行为 |
| --- | --- | --- |
| 站点 | `title`、`description`、`language` | 名称为 `Example Lab`，语言为 `zh_CN`，描述聚焦 Python、AI、Agent、数据采集和工程实践。 |
| 外观 | `appearance.themeColor`、`appearance.banner`、`appearance.favicon` | 默认主题色 hue 为 `140`，主色为 `rgb(20 184 166)`；访客前端自定义色保存在本地 cookie；横幅默认关闭；favicon 留空时使用默认明暗图标。 |
| 作者 | `author.name`、`bio`、`avatar`、`avatarAlt` | 名称为 `Example Lab`，简介为 `记录技术实践与学习笔记`，头像暂用站点图标。 |
| 个人方向 | `author.technologyFocus` | 当前是通用技术方向列表，不代表未经确认的个人经历。 |
| 联系方式 | `author.githubUrl`、`author.contact`、`author.socialLinks` | GitHub 为 `https://github.com/example`，邮箱为 `hello@example.com`，侧栏展示 GitHub 和 Email 链接。 |
| 导航 | `navigation[]` | 首页、归档、关于和主站；主站是外部链接且默认当前标签打开。 |
| SEO | `seo.defaultTitle`、`defaultDescription`、`defaultOgImage`、`twitterCard` | 默认标题和描述已配置；默认分享图为空，Twitter 卡片为 `summary`。 |
| RSS | `rss.enabled`、`title`、`description` | RSS 已启用，端点为 `/rss.xml`。关闭时端点返回 404，页面 alternate 链接和页脚入口也隐藏。 |
| 页脚 | `footer.copyrightHolder`、`showHomeLink`、`homeLinkLabel` | 显示站点版权占位和返回博客首页链接。 |
| 许可证 | `license.enabled`、`name`、`url` | 默认文章许可证为 CC BY-NC-SA 4.0。 |
| 评论 | `features.comments` | 当前开启本地评论。昵称首次访问时从王者荣耀英雄名库随机生成，昵称和评论保存在访客浏览器 `localStorage`，不会同步给其他设备或其他访客。Giscus 代码保留为备选方案，完整配置步骤见 [Giscus 配置](08-Giscus配置.md)。 |
| 统计 | `cloudflareWebAnalytics.*`、`features.analytics` | Cloudflare Web Analytics 接入代码已存在，但当前开关关闭且没有 Token，因此不会加载统计脚本；生产环境还要求 `import.meta.env.PROD`。隐私边界见 [常见问题](13-常见问题.md)。 |
| 功能 | `features.search`、`tableOfContents`、`comments`、`analytics` | 搜索、目录和本地评论开启，统计关闭。 |

## 修改流程

1. 先确认修改属于博客业务配置，而不是主题结构或页面内容。
2. 只编辑 `src/config/site.ts` 中对应字段，避免在组件中复制域名、联系方式、图标路径或文案。
3. 若改变导航，确认内部路径以 `/` 开头，外部地址为完整 HTTPS URL，并正确设置 `external` 与 `openInNewTab`。
4. 若改变 SEO 默认值，检查首页、About、文章和 404 的实际 head 输出。
5. 运行 `pnpm check`、`pnpm type-check` 和 `pnpm build`。

## 作者占位与隐私

当前配置刻意使用明确占位，同时复用顶部变量：

```ts
bio: "记录技术实践与学习笔记"
// 实际配置中通过 authorBio 变量复用
githubUrl
contact: contactEmail
```

当前只确认了 GitHub 主页和邮箱；在收到真实资料前，不要自行补写姓名、经历或其他社交账号。头像替代文本也应描述实际图片，不要把临时图标误写成真实头像。

## 敏感信息

配置文件和文章中禁止写入 Token、密码、私有仓库凭据或个人私密数据。当前：

- 本地评论只写入访客浏览器 `localStorage`，不提供跨设备同步、后台审核或全站公开讨论流。
- Giscus 所需仓库和分类标识为空，未接入第三方评论。
- Cloudflare Web Analytics Token 不存储在仓库中；源码只在生产构建、两个功能开关都打开且 `PUBLIC_CLOUDFLARE_WEB_ANALYTICS_TOKEN` 非空时消费它。
- GitHub 与 Cloudflare Pages Git 集成不依赖仓库内的部署凭据；自定义域已绑定到 Pages，DNS 控制台中 `blog` 为代理 CNAME，根域和其他记录未修改。

## 部署相关状态

业务配置已经固定博客与主站的地址；当前远端部署状态如下：

```text
博客：https://blog.example.com
主站：https://example.com（独立项目，不能在本仓库部署）
```

GitHub 私有仓库为 `example/example-blog`。Cloudflare Pages 项目 `example-blog` 已通过 Git 集成从 `main` 分支成功构建，备用地址为 `https://example-blog.pages.dev`；构建命令为 `pnpm build`，输出目录为 `dist/`，Node.js 为 22，pnpm 为 9.14.4。`https://blog.example.com` 已绑定到 Pages，SSL 已启用。

DNS 维护时只允许处理 `blog.example.com`。当前 Cloudflare 控制台记录为代理 CNAME `example-blog.pages.dev`；根域 `example.com`、`www`、MX/TXT 和其他子域均不得修改。部分递归解析器可能短暂显示迁移前的旧 A 结果，应结合独立 DoH、控制台和 HTTPS 验收判断。详细流程见 [Cloudflare Pages 部署](06-Cloudflare-Pages部署.md)、[域名与DNS配置](07-域名与DNS配置.md) 和 [开发流程与项目交接](15-开发流程与项目交接.md)。

## 环境变量与开关

Giscus 的仓库和分类标识可以通过以下公开构建变量提供，变量名来自 `blogConfig.giscus.environmentVariables`：

```text
PUBLIC_GISCUS_REPO
PUBLIC_GISCUS_REPO_ID
PUBLIC_GISCUS_CATEGORY
PUBLIC_GISCUS_CATEGORY_ID
```

这些值会进入浏览器端配置，不应放入私密变量。仅设置环境变量不会自动启用评论；还必须在配置中打开 `features.comments` 和 `giscus.enabled`，且四个值完整有效。

Cloudflare Web Analytics 使用：

```text
PUBLIC_CLOUDFLARE_WEB_ANALYTICS_TOKEN
```

这是会出现在页面脚本中的站点 Token，不是 Cloudflare API Token；不能把 API Token、密码或其他凭据放进仓库。仅设置 Token 也不会启用统计，必须同时打开 `features.analytics` 与 `cloudflareWebAnalytics.enabled`，并通过生产构建。默认关闭是当前隐私选择。

## 与上游升级的关系

不要用上游 `src/config.ts` 覆盖 `src/config/site.ts`。升级 Fuwari 时，先合并主题类型和默认项，再确认 `blogConfig.appearance`、导航、作者资料、SEO 和功能开关的字段映射仍完整。详见 [上游基线](00-upstream-baseline.md) 与 [主题升级指南](12-主题升级指南.md)。
