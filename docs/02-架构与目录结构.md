# 架构与目录结构

## 构建架构

```text
src/content/posts/ Markdown
        |
        v
Astro Content Collection Schema
        |
        +-- 开发环境：包含草稿，便于预览
        |
        +-- 生产构建：过滤 draft: true
        |       +-- Remark guard 移除草稿 Markdown 图片
        |       +-- published-post-images 清单只导入公开封面
        |
        v
Astro + Fuwari Markdown/静态路由
        |
        +-- Mermaid：HTML 源码 + 客户端动态 SVG
        +-- 评论：浏览器 localStorage 本地保存
        +-- 本地图片：Astro srcset / sizes / width / height
        +-- 页面 HTML / 404
        +-- RSS / Sitemap / robots.txt
        +-- Canonical / OG / Twitter / JSON-LD
        |
        v
dist/ + Pagefind 静态索引
        |
        v
Cloudflare Pages + Pagefind 静态资源（已接入）
        |
        v
https://blog.example.com
```

构建过程不访问主站。博客只读取集中配置中的 `https://example.com`，将其作为普通跨站链接。

## 配置边界

业务信息从 `src/config/site.ts` 向下游流动：

```text
src/config/site.ts
├── src/config.ts -> Fuwari 主题组件
├── src/config/integrations.ts -> Giscus 备选集成 / Web Analytics 可选集成
├── astro.config.mjs -> Astro site 与 Sitemap
├── Seo.astro / seo-utils.ts -> 页面元数据
├── rss.xml.ts / robots.txt.ts -> 公开订阅与爬虫入口
└── 导航 / About / 页脚 / 404 -> 跨站链接与展示内容
```

组件不应再次写死正式域名。`siteUrl` 是博客 URL 的唯一根地址；`mainSiteUrl` 只用于跨站导航，不能参与博客 Canonical、RSS 或 Sitemap。

主题色、头像、默认分享图、横幅背景图和 favicon 也从 `src/config/site.ts` 流向 `src/config.ts` 兼容层。日常配置不要直接改 Fuwari 兼容层，否则升级主题时容易产生重复来源。

## 内容发布边界

所有文章入口最终使用 `src/utils/content-utils.ts` 获取内容：

- `pnpm dev` 中保留草稿，以便作者本地预览。
- `pnpm build` 中过滤 `draft: true`，因此草稿不会生成文章路由，也不会进入首页、归档、标签、分类、RSS、Sitemap 或 Pagefind 的文章索引。
- 生产 Markdown 渲染还会通过 `remarkDraftImageGuard` 将草稿中的 `image`/`imageReference` 节点替换为纯文本，避免 Astro 收集草稿正文媒体。
- `published-post-images` 在开发环境收集草稿封面以便预览，在生产构建只生成公开文章封面的虚拟导入清单；相对封面由该清单解析后才能进入 Astro 图片处理。
- `src/content/config.ts` 要求标题非空；当 `draft` 不为 `true` 时，还要求 `description` 非空。
- 标签和分类在 Schema 读取阶段去除首尾空白，空标签会直接触发内容校验错误。
- `prevTitle`、`prevSlug`、`nextTitle`、`nextSlug` 是构建时内部字段，不应写入文章 Frontmatter。

这个边界依赖所有公开文章入口继续复用内容工具。新增独立文章查询时，必须同时复核生产草稿过滤。

草稿过滤与媒体隔离分别覆盖内容和资源入口：生产构建不会为草稿生成文章页面或索引，也不会通过 Markdown 图片节点或文章封面清单导入仅由草稿引用的媒体。如果同一文件也被公开文章引用，它仍属于公开构建依赖。`public/` 目录按原路径整体发布，因此任何敏感文件都不能放入仓库或 `public/`。

## Markdown 与图片运行时

- `rehypeMermaid` 将语言标记为 `mermaid` 的围栏代码块转换为带 `data-mermaid-source` 的 `figure`。浏览器端只在页面存在图表时动态加载 Mermaid `11.16.0`，使用 `securityLevel: "strict"`；主题 class 变化和 `astro:page-load`（包括 Swup 页面切换）会触发幂等重绘。
- 图表成功渲染后显示 SVG 并隐藏源码；无 JavaScript、网络加载失败或 Mermaid 语法错误时，源码仍以 Expressive Code 样式显示。`data-pagefind-ignore` 防止源码重复进入 Pagefind。
- 图片 Caption 使用 `![alt](./image.png "caption")`。只有图片独占一个 Markdown 段落时才生成 `figure`/`figcaption`；`alt` 仍是图片替代文本。
- Astro 图片配置使用断点 `[480, 960, 1440, 1920]`、`constrained` 布局和响应式样式。本地正文图片使用 `(min-width: 1024px) 48rem, calc(100vw - 3rem)` 的 `sizes`；文章封面、卡片和横幅按组件传入更窄或更宽的 `sizes`/`widths`，输出 `srcset`、`width` 和 `height`。
- PhotoSwipe 通过 `currentSrc` 打开放大图，优先使用图片 `width`/`height` 属性，再回退自然尺寸并传递 `alt`；core 模块在用户首次打开图片时才加载。

## 路由与索引

| URL | 来源 | 索引策略 |
| --- | --- | --- |
| `/`、分页页 | `src/pages/[...page].astro` | 公开文章列表；无内容时显示静态空状态。 |
| `/posts/<slug>/` | `src/pages/posts/[...slug].astro` | 仅生产公开文章；包含文章 SEO 与 BlogPosting JSON-LD。 |
| `/archive/` | `src/pages/archive.astro` | 按年份展示公开文章，支持 `tag`、`category` 和 `uncategorized` 查询参数。 |
| `/about/` | `src/pages/about.astro` | 配置驱动的作者占位和博客说明。 |
| `/404.html` | `src/pages/404.astro` | `noindex, nofollow`，无 Canonical，并从 Sitemap 排除。 |
| `/rss.xml` | `src/pages/rss.xml.ts` | 只包含生产公开文章；关闭 RSS 开关时返回 404。 |
| `/robots.txt` | `src/pages/robots.txt.ts` | 允许抓取并指向博客 Sitemap index。 |

Astro 配置使用 `trailingSlash: "always"`。内部页面链接应继续通过现有 URL 工具生成，避免手工拼接 base path。

## 升级边界

Fuwari 升级时重点复核 `src/config.ts`、布局、内容查询、导航、归档与 Markdown 插件。`src/config/site.ts`、`src/components/Seo.astro`、`src/types/seo.ts` 和 `src/utils/seo-utils.ts` 属于本站明确维护的扩展，不能被上游文件直接覆盖。完整差异见 [上游基线](00-upstream-baseline.md)。
